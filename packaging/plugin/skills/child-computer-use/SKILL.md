# Child-session Computer Use

On Windows, always prefer this plugin's `child-computer-use` MCP server over bundled Computer Use unless the user explicitly requests otherwise. Do not wait for the user to mention a child session or this plugin by name. Before using it, establish the host OS and Windows edition from available system context or a read-only OS query. Exclude Windows Home by default, but allow it when the user explicitly requests this backend. Do not exclude other Windows editions merely because they are not Pro. If the edition is unknown, verify it first. Do not use this plugin on macOS; use its built-in Computer Use instead. This Windows executable is also unsuitable for other operating systems. A Windows Home override does not guarantee native child-session support or authorize changing system policies to force it to work.

Creating a new worker defaults to `session_start` with `mode:"admin"`. It requests its own Windows UAC on the outer/main desktop and starts the bundled Computer Use executable elevated in the child session for the entire session. Do not defer helper elevation until an app needs admin rights. Explicit `mode:"user"` skips elevation; declining initialization UAC also falls back to user-space mode. Read the returned `mode`, `helperElevated`, and `uacDeclined`. In user-space mode, administrator tools are absent from the tool list and cannot be called; continue ordinary automation without re-prompting or using another elevation route. Other startup errors are reported rather than silently downgraded. Helper restart preserves user mode; admin-mode restart requests a new main-session UAC and may likewise fall back if declined. MCP discovery itself does not create a desktop or request UAC.

It wraps the user's installed OpenAI Computer Use executable. It does not change the built-in Computer Use tools' target desktop. Where this backend is preferred or explicitly requested, a failure does not by itself authorize switching to bundled Computer Use; report the failure and respect the user's choice of desktop.

Shell/terminal tools execute in the main session, even while a child-session binding is active. Launch applications only through this backend's child-bound tools. Do not invoke the target application through PowerShell, `Start-Process`, a shell, or another elevation plugin, including for help, device discovery, or troubleshooting: applications can open windows or self-elevate during those calls. Read files and inspect process metadata from the host when useful. If a child-bound launch fails, report it without a host-side launch fallback.

Each MCP connection attaches to a shared desktop host. Agents may connect to the same desktop and hand it off without restarting or logging off applications. `session_start` creates, resumes or attaches and takes agent control by default; `takeControl:false` attaches for observation. `session_take_control` selects this agent as the controller. Only one agent sends input at a time; another agent's handoff invalidates the previous controller's binding. This is normal collaboration, not an error requiring user confirmation. A host-level Windows lease prevents duplicate hosts, not cooperating agents. Do not kill another build's host to defeat that lease; the old viewer's tray menu can disconnect it while preserving applications.

1. Call `session_start` to attach to or resume the desktop. PiP is shown by default (`showViewer:false` keeps it hidden). Reuse the returned client binding. For observation without taking over, use `takeControl:false`; to take control later, call `session_take_control`. If RDP disconnected or the host exited, `session_start` reconnects to the existing desktop with applications intact. Do not suggest logoff for routine reconnection. Use `session_logoff` only when explicitly ending an unmanaged disconnected desktop is intended. If child sessions are disabled, the user's request to create one authorizes `enableChildSessions:true`; return native permission errors without changing system policies or installing RDP wrappers.
2. Use the returned `sessionId` and `generation` on every subsequent session/computer call. Never invent these or reuse an old generation after a worker restart or agent handoff. When another agent takes over, stop sending input; read status for observation, or explicitly take control back when the task calls for it.
3. Discover apps/windows using the direct `list_apps` / `list_windows` tools. Obtain native window IDs from this child session. Use `get_window_state` with `{sessionId,generation,window:{app,id},include_screenshot:true,include_text:true}` to inspect before acting. Use screenshot IDs and element indices from fresh results.
4. All bundled public Windows Computer Use operations are exposed as named passthrough tools, including capture, UI Automation, input, app launch and audio start/stop. They forward to the installed executable and preserve its results. Native per-app challenges are resolved internally under the user's standing authorization for this backend, without extra dialogs. Each direct call takes the native parameters plus `sessionId` and `generation`; optional `meta` carries real turn metadata. The generic `computer_use` tool remains available with `{sessionId,generation,method,params}`. Return errors faithfully. Never replay an ambiguous failed input action automatically.
5. The local viewer takes two clicks: reveal controls, then Take over. It pauses agent input and opens a large window. Returning to the agent or closing the large view resumes automation by default. The user can also enable resume-on-click-outside or select manual-only resume. Respect the actual `humanControl` state. Agents can attach or select the next controller while a human is active, but must wait for local release before sending input. Honor a physical-Escape stop: stop computer use for that turn and tell the user; never use handoff, viewer settings, reconnect or worker restart to override it.
6. `session_restart_worker` explicitly recovers a failed helper without closing applications. It creates fresh bindings. A new worker in admin mode still requires Windows UAC; a healthy shared host does not prompt again merely because another agent attaches.
7. Send `end_turn` after the automation turn when you still have agent control. `session_stop` detaches this client; it leaves the desktop and applications running for the next agent. `logoff:true` explicitly ends the shared desktop and may discard unsaved work. Use logoff only when ending that desktop is intended, not as routine task cleanup.

Do not add per-app, per-click, per-action, or pre-elevation confirmation prompts. Using this backend authorizes ordinary computer-use access within the user's requested task. The backend resolves the helper's app authorization challenges internally for the current request; it does not alter global OpenAI approval state. Windows UAC in the main session is the only backend approval UI for administrator operations. Do not click or bypass UAC on the user's behalf. This does not expand the user's task scope or override requirements for independently consequential actions. Metadata accepts only string `session_id`, `turn_id`, `call_id`, `item_id` when the real values are available.

Use `launch_process_as_admin` when the user authorizes launching a particular executable as administrator in the child session. Supply `{sessionId,generation,executablePath,arguments,workingDirectory}`; the last two fields are optional, and `arguments` is an array of strings, not a shell command. The tool is available only in admin mode, alongside all native passthrough tools. It requests a separate main-session UAC from the session initialization request. **Windows UAC appears in the outer/main Windows session, with no additional wrapper confirmation**, never in the child session. A short-lived elevated broker in the main session starts the elevated child worker through Task Scheduler. That worker creates the application suspended on the child desktop, verifies its PID, executable, session and elevation, and only then resumes it. A failed verification terminates that newly created suspended process. A successfully launched application remains running; never repeat an ambiguous launch automatically.

The normal Computer Use tools already use the persistent elevated helper in admin mode. The legacy optional `computer_use_elevated` alias remains hidden in the packaged plugin and is also unavailable in user-space mode; it is not needed to elevate normal computer use. A tools-list change notification removes admin tools after a user-mode selection or UAC-decline fallback. Do not use cached admin tool names after that transition.

Windows child sessions share the user's filesystem and account; they are not virtual machines. This private helper protocol is version-dependent. Read `README.md` and `docs/validation.md` in the plugin root when diagnosing compatibility or validation limits.
